# Next.js admin A2 admin 뼈대 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 독립 템플릿 `templates/nextjs-admin/`을 만든다. 비밀번호 로그인과 `admin:access` 판정, 관리 레이아웃, 계약 타입으로 검사하는 리소스 선언과 범용 목록·상세·폼, 글 골든, 리소스 생성기, 하네스, 목 E2E 11개, CI 작업 `nextjs-admin`이 들어간다. A1이 남긴 overlay 후속 정리도 마친다.

**Architecture:**

- Task 1: overlay 기록을 대상별로 나눠 두 번째 대상이 기존 기록을 물려받지 않게 하고, 원본은 git 인덱스 파일만 고르며, 원본 자동 수정 명령을 둔다.
- Task 2–4: web의 앱 파일로 admin 골격을 만들어 사본·의존성 버전·CI에 등록하고, 공유 UI 부품을 더한 뒤 로그인·권한·레이아웃을 올린다.
- Task 5–7: 리소스 하나는 선언 하나다. 선언은 생성 계약 타입으로 검사되고, server-only 데이터 계층과 범용 화면·Server Action이 선언을 그린다.
- Task 8–9: 글 골든·실시간·E2E로 프레임워크를 확인하고, 계약에서 선언 초안을 만드는 생성기와 문서로 마친다.

## Global Constraints

모든 태스크의 요구 사항은 이 목록을 포함한다.

**Docker와 데이터**

- 로컬에서 Docker를 쓰지 않는다. Docker Desktop을 시작하지 않고 `docker`·`docker compose` 명령을 실행하지 않는다.
- 이 PC의 compose 프로젝트 `fastapi`(볼륨 `fastapi_postgres-data`·`fastapi_seaweedfs-data`)와 `joon`은 쓰지도, 내리지도, 지우지도 않는다.
- 금지 명령: `pnpm conformance fastapi`, `pnpm web-e2e fastapi`, `templates/fastapi` 안의 `uv run poe setup|dev|check|test|test:e2e|e2e:serve|db:*`.
- web의 FastAPI E2E와 이미지 빌드(web·admin)는 PR CI(`nextjs-e2e-fastapi`, `nextjs`, `nextjs-admin`, `create-combo`, `create-standalone`)에서만 확인한다.
- `.env`를 읽거나 출력하지 않는다. `.env.example`은 읽어도 된다.

**독립성과 사본**

- `templates/<이름>/` 안의 파일(문서 포함)은 템플릿 밖 경로를 참조하지 않는다. 템플릿 지침·문서는 저장소의 `shared/`를 언급하지 않는다(템플릿 안의 `messages/shared/`는 자기 경로다).
- 공유 코드는 `shared/nextjs/`에서만 고친다. 새 원본은 `git add` → `pnpm fix:shared <원본 파일...>`(Task 1부터) → `pnpm sync` 순서다. 템플릿의 공유 사본과 그 `pnpm fix`로 사본을 고치지 않는다. 태스크를 마칠 때 `pnpm sync` 뒤 `git status --short`가 빈다.
- 공유 파일은 앱 중립이다. 앱 이름·포트·쿠키 이름·경로 목록·앱 문구를 쓰지 않고 고정 앱 파일 여덟 개(§3.3)만 import한다. `scripts/test/sync/shared-nextjs.test.ts`가 고정한다.

**동작과 버전**

- web은 이전과 똑같이 동작한다. 공유 원본이나 `templates/nextjs`를 바꾼 태스크(2, 3)는 web check·build·목 E2E 20개를 확인한다.
- admin은 web과 같은 스택·버전이다(AD2). 두 템플릿에 함께 있는 의존성(dependencies·devDependencies·overrides)은 버전이 같다. 의존성과 잠금 파일을 바꾸지 않는다. 꼭 더해야 하면 정확히 고정하고 `minimumReleaseAge` 1440분을 지키며(`pnpm view <패키지>@<버전> time`), 공유 파일이 쓰면 두 템플릿에 함께 더한다.

**UI**

- 로딩은 스피너(`Spinner`, `Loader2`)나 스켈레톤만 쓰고 로딩 문구를 쓰지 않는다(check가 강제한다). 다크 모드는 시스템 설정만 따른다(web N5).
- 폼은 Server Action과 `useActionState`로 만들고 폼 라이브러리를 쓰지 않는다(web N4).

**테스트**

- BFF 통합 테스트는 실제 목 프로세스에 붙인다(web N16, `inject("mockBaseUrl")`).
- Base UI 팝업(Select·Dialog·Sheet)이 연 요소는 `await screen.findByRole(...)`로 기다리고, 닫힘은 `await waitFor(...)`로 확인한다. 클릭 직후 `getByRole`로 찾지 않는다(run 37739790756).
- 테스트 출력에 경고가 없다. admin의 `NextIntlClientProvider`·`createTranslator`는 `scripts/test/intl-fixture.ts`의 `intlFixture(messages, locale = "ko")` → `{ locale, messages, timeZone: envSchema.shape.TIME_ZONE.parse(process.env.TIME_ZONE) }`를 펼쳐 받는다(Task 4가 만든다). 확인: `pnpm --dir templates/nextjs-admin test --reporter=verbose --silent=false 2>&1 | grep -c -E "stderr \||Warning|ENVIRONMENT_FALLBACK"` → `0`.
- 테스트는 자기가 만든 임시 폴더를 지운다. 새 임시 폴더는 OS 임시 폴더의 `aitpl-`로 시작하는 이름이다. 다른 에이전트를 부르지 않는다.

**문구와 커밋**

- 문서·주석·검사·CLI 출력·UI 문구는 짧은 한국어다. 실패 메시지는 `<문제> — <방법>` 꼴이다.
- 경로·키·포트·이름 같은 바뀌는 값 바로 뒤에 조사를 붙이지 않는다. 값은 `:` 앞이나 괄호 안에 둔다(`e9a3ba5`). 새로 쓰는 테스트 제목의 `%s`·`%j` 뒤도 같다(기존 제목은 그대로 둔다). 이 계획과 참고 구현에서 옮기는 메시지·문구는 글자 그대로 쓴다.
- 태스크마다 커밋 하나. 영어 Conventional Commits, 트레일러·AI 표시 없음, `--no-verify` 금지, 텍스트 파일만.

### Task 1: 저장소 — 대상별 overlay 기록과 원본 관리 (§3.1, §3.3, §3.6)

참고 구현: `6c9c901`. 그대로 따를 것: 대상 `managedFiles`의 형식과 판정, 원본 선택, 삭제 줄, `fix:shared`의 동작과 메시지, 테스트(`overlay.test.ts`의 새 테스트 여섯, `fix-nextjs.test.ts` 둘), 문서가 말하는 순서. 자유: 함수 나누기, 그 밖의 문장. 이 계획이 바꾼 것: 원본에만 있는 import를 따로 알린다(A1에서 미룬 항목, 참고 구현에 없다). 대상 기록 테스트 제목은 `대상의 잘못된 삭제 기록은 쓰기 전에 거절한다: %j`다.

**Files:**

- Modify: `scripts/src/verify-templates/{manifest,verify}.ts`, `scripts/src/sync/sync.ts`, `scripts/test/sync/{overlay,shared-nextjs}.test.ts`, `scripts/shared-assets.json`(sync가 쓴다), 루트 `package.json`(`"fix:shared": "node scripts/src/sync/fix-nextjs.mjs"`)
- Create: `scripts/src/sync/fix-nextjs.mjs`, `scripts/test/sync/fix-nextjs.test.ts`
- Modify(문서): `scripts/src/sync/README.md`, `AGENTS.md`, `docs/harness/standard.md`, spec §3.1·§3.3·§3.6

**Interfaces:**

- Consumes: A1의 `SharedAsset`, `overlayFiles`, `managedFiles`, `syncSharedAssets`, `verifyTemplate`, `readSharedAssets`, `gitEnvironment()`(`scripts/src/files/git-environment.ts`).
- Produces(Task 2가 대상 `nextjs-admin`을 더할 때 쓴다):
  - `SharedAssetTarget = { readonly template: string; readonly path: string; readonly managedFiles?: readonly string[] }`, `SharedAsset.targets: readonly SharedAssetTarget[]`. 대상 기록은 overlay 전용이고 항목 기록과 같은 형식 검사·메시지를 쓴다(위치 `assets[i].targets[j].managedFiles`).
  - `overlayFiles(repoRoot, asset): string[]` — 원본 폴더의 `git ls-files --cached -z -- .`(cwd 원본, env `gitEnvironment()`) 중 디스크에 있는 안전한 경로, 정렬. 미추적 파일은 복사·기록하지 않는다.
  - `targetManagedFiles(repoRoot, asset, target): string[]` — `overlayFiles` ∪ (`target.managedFiles` ∩ `asset.managedFiles`), 정렬. sync·사본 검사·쓰기 검사가 이것을 쓴다.
  - "기록됨"은 대상마다 `target.managedFiles` ∩ `asset.managedFiles`다. 새 대상은 다른 대상의 기록을 물려받지 않는다. 현재 원본 경로는 빈 자리나 같은 바이트만 받고(다르면 A1의 "앱 파일 자리" 오류), 이미 지운 원본 경로의 앱 파일은 지우지 않는다. 대상 기록이 없는 이전 형식도 미기록으로 본다. 원본의 링크·폴더 검사는 디스크의 모든 원본 파일(`node_modules` 제외)을 계속 본다.
