# Next.js admin A1 공유 원본 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** web과 admin이 함께 쓸 코드를 원본 `shared/nextjs/` 하나에 두고, `pnpm sync`가 `templates/nextjs`의 같은 경로에 같은 바이트로 덮어 놓게 한다. web은 세션 쿠키 이름 말고는 그대로 동작한다.

**Architecture:**

- Task 1: 저장소 sync에 `mode: "overlay"` 항목을 더한다. 원본 폴더의 파일만 대상의 같은 상대 경로에 쓰고, manifest의 `managedFiles` 기록으로 지운 원본의 사본도 찾는다.
- Task 2~4: web 안에서 앱마다 다른 값(앱 이름·포트·쿠키 이름·계약 위치)을 설정 파일로 빼고, 메시지를 공유·앱 카탈로그로 나누고, web 전용 코드가 섞인 파일을 고정 이름의 앱 파일로 나눈다. 그러면 공유할 파일 132개가 앱 중립이 된다.
- Task 5: 그 132개를 `shared/nextjs/`로 복사해 overlay 항목으로 등록한다. 템플릿 파일은 바뀌지 않는다.

**Tech Stack:** 버전을 바꾸지 않는다. 저장소는 Node 24, pnpm 12.6.0, TypeScript 6.0.3, tsx 4.23.15, Vitest 5.0.1, Prettier 3.9.9, ESLint 10.11.0. web은 Next.js 16.3.8, React 19.3.0, next-intl 4.14.7, zod 4.6.5, eslint-plugin-boundaries 7.2.0, @playwright/test 1.63.0, openapi-typescript 7.13.0. 새 의존성은 없다.

**Spec:** `docs/superpowers/specs/2026-10-08-nextjs-admin-design.md`(이하 §N)의 §3, AD3·AD8·AD9·AD10·AD11, §8.5, §10·§11의 A1 행, §12의 2~4. §3.1·§3.2의 최종 문단은 프로토타입 `ffefa31`판이 기준이고 Task 5가 옮긴다. 배경은 기반 설계 §3.1~§3.3, web 설계 §4·§5·§9, `docs/harness/standard.md`다.

**참고 구현:** 브랜치 `feature/admin-a1-proto`의 검증된 커밋 넷(main `3be4f2a` 위). Task 1 `69a8ec7`, Task 2 `3e1bf2b`, Task 3 `101eefa`, Task 4는 `ffefa31`의 `templates/` 변경, Task 5는 `ffefa31`의 나머지다. 읽고 옮겨도 된다. 이 계획이 다르게 정한 것(메시지 문구, Review Focus 검사)은 계획을 따른다. `ffefa31`은 draft PR #5의 CI(run `37708749520`)에서 8개 작업이 모두 통과했다(web FastAPI E2E `nextjs-e2e-fastapi` 포함).

**태스크 경계:** 프로토타입 커밋마다 한 태스크이고 `ffefa31`만 둘로 나눴다. web 안의 혼합 파일 분리(35개 파일, 설계 판단)와 132개 복사·등록·문서(기계적 작업)는 `templates/` 안팎으로 깔끔히 갈리고, 리뷰어가 한쪽만 반려할 수 있다. Task 2는 앱 설정과 계약 위치가 같은 실행기(dev, E2E, 목 헬퍼, check)를 함께 고치므로 나누지 않는다.

## Global Constraints

모든 태스크의 요구 사항은 이 목록을 포함한다.

**Docker와 데이터**

- 로컬에서 Docker를 쓰지 않는다. Docker Desktop을 시작하지 않고 `docker`·`docker compose` 명령을 실행하지 않는다.
- 이 PC의 compose 프로젝트 `fastapi`(볼륨 `fastapi_postgres-data`·`fastapi_seaweedfs-data`)와 `joon`은 쓰지도, 내리지도, 지우지도 않는다.
- 금지 명령: `pnpm conformance fastapi`, `pnpm web-e2e fastapi`, `templates/fastapi` 안의 `uv run poe setup|dev|check|test|test:e2e|e2e:serve|db:*`.
- web의 FastAPI E2E와 조합 생성은 PR CI(`nextjs-e2e-fastapi`, `create-combo`, `create-standalone`)에서만 확인한다.
- `.env`를 읽거나 출력하지 않는다. `.env.example`은 읽어도 된다.

**독립성과 사본**

- `templates/<이름>/` 안의 파일(문서 포함)은 템플릿 밖 경로를 참조하지 않는다. 템플릿 지침·문서는 저장소의 `shared/`를 언급하지 않는다. 템플릿 안의 `messages/shared/`는 템플릿 자기 경로다.
- 공유 사본은 루트 `pnpm sync`로만 만든다. 태스크를 마칠 때 `pnpm sync` 뒤 `git status --short`가 비어 있다.
- `shared/nextjs/`는 독립 프로젝트가 아니다. 루트 ESLint·Prettier가 `templates/**`처럼 제외하고, 사본의 web check가 검사한다.

**동작과 버전**

- web은 세션 쿠키 이름(개발 `web-session`, 운영 `__Host-web-session`, AD8) 말고는 이전과 똑같이 동작한다. 메시지 키·문장, 화면 경로, 보호 경로, 포트, E2E 시나리오가 그대로다.
- 의존성과 잠금 파일을 바꾸지 않는다. 꼭 더해야 하면 정확한 버전으로 고정하고 `minimumReleaseAge` 1440분을 지킨다(`pnpm view <패키지>@<버전> time`).

**문구와 커밋**

- 문서·주석·검사·CLI 출력은 짧은 한국어다. 실패 메시지는 `<문제> — <방법>` 꼴이다.
- 경로·키·포트 같은 값 바로 뒤에 조사를 붙이지 않는다. 값은 `:` 앞뒤나 괄호 안에 둔다(`e9a3ba5`의 관례). 이 계획에 적은 메시지는 글자 그대로 쓴다.
- 태스크마다 커밋 하나. 영어 Conventional Commits, 트레일러·AI 표시 없음, `--no-verify` 금지, 텍스트 파일만.
- 테스트는 자기가 만든 임시 폴더를 지운다. 새 테스트의 임시 폴더는 OS 임시 폴더에 `aitpl-`로 시작하는 이름으로 만든다. 다른 에이전트를 부르지 않는다.

**완료 기준(태스크마다, 한 번에 하나씩 차례로)**

1. 루트 `pnpm check` → `check 통과: 11단계, …`(format, lint, agents-md, templates, workflows와 workspace 여섯: api-style, conformance, mock, contract, scripts, create).
2. `templates/nextjs`를 바꾼 태스크(2~4): `templates/nextjs/.cache/check.json`을 지우고 그 폴더에서 `pnpm check` → `check 통과: 9단계 (0 캐시)`, `pnpm build` → exit 0, `pnpm test:e2e`(목) → `20 passed`. 9단계는 format, lint, types, tests, generated, i18n, contract-typespec, contract-mock, harness다.
3. 루트 `pnpm sync` 뒤 `git status --short`가 빈다. 출력은 Task 4까지 10줄, Task 5부터 `shared/nextjs → templates/nextjs/.`이 더해진 11줄이다.

**Interfaces:**

- Consumes: 기존 `readSharedAssets(repoRoot): SharedAssetsManifest | string[]`, `sharedAssetsProblems(repoRoot, manifest): string[]`, `syncSharedAssets(repoRoot, manifest): string[]`, `verifyTemplate(repoRoot, template, manifest): string[]`, `sameFile`. 검사 CLI는 manifest 문제 앞에 `scripts/shared-assets.json: `을, 템플릿 문제 앞에 `templates/<이름>: `을 붙인다.
- Produces(A2가 대상 `nextjs-admin`을 더할 때 쓴다):
  - 항목 `{ "source": "shared/nextjs", "mode": "overlay", "targets": [{ "template": "nextjs", "path": "." }], "managedFiles": [...] }`. `mode`가 없으면 지금처럼 통째로 교체한다. `managedFiles`는 overlay 전용이고 sync가 쓴다. 현재 원본 파일과 이전 기록의 정렬된 합집합이며 지운 경로도 남는다.
  - `SharedAsset = { readonly source: string; readonly mode?: "overlay"; readonly managedFiles?: readonly string[]; readonly targets: readonly { readonly template: string; readonly path: string }[] }`
  - `copyPath(repoRoot: string, template: string, path: string, overlay = false): string | undefined` — overlay면 템플릿 루트(`"."`, `""`)도 돌려준다.
  - `overlayFiles(repoRoot: string, asset: SharedAsset): string[]` — 원본의 모든 파일, `/` 구분. 숨김 파일과 `.cache`는 넣고 모든 깊이의 `node_modules`는 뺀다.
  - `managedFiles(repoRoot: string, asset: SharedAsset): string[]` — `overlayFiles`와 `asset.managedFiles`의 정렬된 합집합.
  - `listFiles(dir: string, ignored: ReadonlySet<string> = new Set(["node_modules", ".cache"])): string[]`
  - sync 출력 줄 `<source> → templates/<template>/<path>`(예: `shared/nextjs → templates/nextjs/.`).
  - 사본 검사 메시지. `<사본>`은 템플릿 기준 `/` 경로다(루트 대상이면 `src/lib/utils.ts`, 대상이 `base`면 `base/src/lib/utils.ts`).
    - 현재 원본의 사본이 다르거나 없다: `<사본>: 사본이 원본과 다르다 — 원본(<source>/<file>)을 고친 뒤 pnpm sync한다.`
    - 지운 원본의 사본이 남았다: `<사본>: 지운 원본(<source>/<file>)의 사본이 남았다 — 앱 파일로 두려면 managedFiles에서 이 경로를 빼고, 아니면 pnpm sync로 지운다.`

const raw = (repo: string) =>
  JSON.parse(read(repo, "scripts/shared-assets.json")) as SharedAssetsManifest;

it("기록에 없는 새 원본은 다른 내용의 앱 파일을 덮지 않는다", () => {
  const repo = makeRepo();
  syncSharedAssets(repo, load(repo));
  write(repo, "shared/nextjs/src/lib/local.ts", "// 공통 판\n");
  expect(readSharedAssets(repo)).toEqual([
    "templates/web/src/lib/local.ts: 앱 파일 자리에 새 원본(shared/nextjs/src/lib/local.ts)을 쓸 수 없다 — 앱 파일을 옮기거나 원본과 같은 내용으로 맞춘 뒤 pnpm sync한다.",
  ]);
  expect(() => syncSharedAssets(repo, raw(repo))).toThrow(/앱 파일 자리/);
  expect(read(repo, "templates/web/src/lib/local.ts")).toBe("// 앱 파일\n");
  write(repo, "shared/nextjs/src/lib/local.ts", "// 앱 파일\n");
  syncSharedAssets(repo, load(repo));
  expect(load(repo).assets[0]?.managedFiles).toContain("src/lib/local.ts");
});

it("지운 원본의 사본은 기록에서 빼면 앱 파일로 남는다", () => {
  const repo = makeRepo();
  syncSharedAssets(repo, load(repo));
  rmSync(join(repo, "shared/nextjs/src/lib/cookie.ts"));
  expect(verifyTemplate(repo, "web", load(repo))).toEqual([

  syncSharedAssets(repo, load(repo));
