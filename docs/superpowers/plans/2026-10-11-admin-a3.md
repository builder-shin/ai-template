# Next.js admin A3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사용자·역할·권한·감사 로그 제품 리소스와 그것이 쓰는 범용 선언·폼 확장, 로그인 복귀, admin FastAPI E2E, create CLI의 단독 admin과 FastAPI+web/admin 조합(루트 계약 하나)을 더하고, macOS 프로세스 그룹 정리와 문서·기록을 맞춘다.

**Architecture:**

- Task 1–2: macOS의 모든 프론트·루트 검사가 거치는 두 프로세스 정리 helper를 먼저 고친다.
- Task 3–7: 선언·폼을 계약 타입으로 좁히고 로그인 복귀를 고친 뒤, 생성기 초안에서 시작해 리소스 넷을 차례로 등록한다. 리소스가 필요로 하는 범용 변경은 fixture 선언 테스트와 함께 그 태스크에 둔다.
- Task 8: web E2E 실행기를 앱 설정으로 넓혀 admin FastAPI E2E와 FastAPI 실시간 기본값을 더한다.
- Task 9–11: 조합 계약을 루트로 옮기고, CLI를 프론트 목록으로 일반화한 뒤, admin 조합과 잠금·workspace 합치기를 더한다. Task 12가 스펙·하네스·문서·테스트 제목을 맞추고 A3 기록을 남긴다.

## Global Constraints

모든 태스크의 요구 사항은 이 목록을 포함한다.

**Docker와 데이터**

- 로컬에서 Docker를 쓰지 않는다. Docker Desktop을 시작하지 않고 `docker`·`docker compose` 명령을 실행하지 않는다.
- compose 프로젝트 `fastapi`(볼륨 `fastapi_postgres-data`·`fastapi_seaweedfs-data`)와 `joon`은 쓰지도, 내리지도, 지우지도 않는다.
- 금지 명령: `pnpm conformance fastapi`, `pnpm web-e2e fastapi`·`pnpm admin-e2e fastapi`(둘 다 계획만 출력하는 `--print`만 허용), `templates/fastapi`의 `uv run poe setup|dev|check|test|test:e2e|e2e:serve|gen|db:*`. FastAPI Stop hook도 인프라를 쓴다.
- `templates/fastapi`에서 허용: `uv sync --frozen`, `uv run ruff format --check .`, `uv run ruff check .`, `uv run basedpyright`, `uv run python -m tools.checks architecture`, `uv run python -m tools.checks harness`, 인프라 fixture가 없는 `uv run pytest src/app/core/tests/test_config.py tools/tests/test_e2e.py tools/tests/test_env_example.py`.
- `pnpm new`는 OS 임시 폴더의 `aitpl-`로 시작하는 새 폴더에만 만든다(레지스트리 접속 필요, Docker 불필요). 생성 조합에서는 `pnpm --filter <web|admin> check|build|run gen`만 실행한다. 조합 루트의 `pnpm setup|dev|check|test|test:e2e|db:*`, `apps/api`의 위 허용 밖 명령, compose는 실행하지 않는다. 단독 nextjs·nextjs-admin 생성물의 `pnpm setup`·`pnpm check`는 허용한다.
- Docker가 필요한 확인은 PR CI의 열 작업에서만 한다: `check`, `fastapi`, `nextjs`, `nextjs-admin`, `nextjs-e2e-fastapi`, `nextjs-admin-e2e-fastapi`(Task 8부터), `conformance-fastapi`, `conformance-mock`, `create-combo`, `create-standalone`.
- `.env`를 읽거나 출력하지 않는다. `.env.example`은 읽어도 된다.

**독립성·사본·계약**

- `templates/<이름>/` 안의 파일(문서 포함)은 템플릿 밖 경로, 저장소의 `shared/`, 마일스톤 이름(`A3` 등)을 쓰지 않는다. 템플릿 안 `messages/shared/`는 자기 경로다.
- 공유 코드는 `shared/nextjs/`에서만 고친다. 기존 원본은 `pnpm fix:shared <원본...>` → `pnpm sync`, 새 원본은 `git add` → `pnpm sync` → `pnpm fix:shared <원본...>` → `pnpm sync` 순서다. 사본과 템플릿 `pnpm fix`로 공유 사본을 고치지 않는다. 공유 파일은 앱 중립이며 고정 앱 파일 여덟 개(§3.3)만 import한다.
- 새·삭제 공유 파일의 항목·대상 `managedFiles`는 sync가 `scripts/shared-assets.json`에 기록한다. 앱 소유로 돌리는 파일은 먼저 항목과 대상 기록에서 뺀다(`scripts/src/sync/README.md`).
- 계약은 `contract/typespec/src/`만 고치고 `pnpm gen`한다. `contract/openapi.yaml`, `**/generated/**`, `src/lib/api/schema.d.ts`는 직접 고치지 않는다. 이 계획에는 계약 변경이 없다. 계약·목·규약 사본은 루트 원본을 고친 뒤 `pnpm sync`로 맞춘다.

**버전**

- 두 프론트의 공통 dependencies·devDependencies·overrides 버전과 `pnpm-workspace.yaml`의 `minimumReleaseAge`(1440)·`allowBuilds`·`overrides`는 같다(workspace 세 값의 저장소 검사는 Task 11). 의존성과 잠금 파일을 바꾸지 않는다. 꼭 더하면 정확히 고정하고 `pnpm view <패키지>@<버전> time`으로 1440분을 확인한다.
- 생성 조합은 `overrides.typescript` 6.0.3을 유지하고 루트에 TypeScript 직접 의존성을 넣지 않는다.

**UI·권한·테스트**

- 로딩은 스피너(`Spinner`, `Loader2`)나 스켈레톤만 쓰고 문구를 쓰지 않는다. 다크 모드는 시스템 설정만 따른다. 폼은 Server Action과 `useActionState`이며 폼 라이브러리는 없다.
- 화면은 할 수 없는 것을 숨기지만 최종 판단은 API다. Server Action은 권한과 최신 레코드를 다시 확인한다. 401은 로그인, 그 밖의 4xx는 그 자리 안내다(§4.7).
- BFF 통합 테스트는 실제 목 프로세스(`inject("mockBaseUrl")`)에 붙는다. Base UI 팝업이 연 요소는 `await screen.findByRole(...)`, 닫힘은 `await waitFor(...)`로 기다린다. 번역은 `scripts/test/intl-fixture.ts`의 `intlFixture`를 쓴다.
- E2E는 시나리오마다 새 계정·새 브라우저 컨텍스트다. 시드 관리자는 API 역할 준비만 하고 브라우저에 로그인하지 않는다. 실시간 변경은 새 페이지의 subscribe ACK(`subscriptionCount`) 뒤에만 만든다. 행위자는 백엔드의 권한 상승 규칙을 지킨다: 자기 권한 안의 사용자·역할만 바꾸고 자기 자신은 바꾸지 못한다.
- 테스트는 만든 임시 폴더를 지운다. 새 임시 폴더는 OS 임시 폴더의 `aitpl-` 이름이다. 다른 에이전트를 부르지 않는다.

**테스트 경고**

- admin Vitest 경고는 0이다. web Vitest는 기존 17 stderr 블록만 예외로 받는다: `src/components/layout.test.tsx` 2, `src/features/auth/login-form.test.tsx` 1, `src/features/auth/password-reset-form.test.tsx` 2, `src/features/auth/signup-form.test.tsx` 3, `src/features/files/profile-upload.test.tsx` 2, `src/features/files/upload.test.tsx` 2, `src/features/me/deletion-form.test.tsx` 1, `src/features/me/forms.test.tsx` 2, `src/features/posts/editor.test.tsx` 1, `src/features/sessions/components.test.tsx` 1. 블록 안 진단은 React act 17·Base UI defaultValue 2·nativeButton 1이며 겹치므로 합이 블록 수가 아니다. 파일·메시지·횟수가 같아야 하고 제목 변경만 명시한 매핑으로 정규화한다. 새 경고는 실패다. 경고를 숨기거나(console mock, silent) 관련 없는 제품 코드를 고치지 않는다.
- 확인: OS 임시 폴더의 스크립트를 `bash <파일> templates/<이름>`으로 실행한다. web은 gen-feature 사본의 중첩 요약 `Tests 96 passed (96)`이 먼저 보일 수 있다. 파일별 블록 수는 `grep -o -E 'stderr \| [^ ]+' <로그> | sort | uniq -c`로 위 목록과 비교한다.

```sh
#!/usr/bin/env bash
# 템플릿 Vitest의 요약 줄과 경고 수를 보인다.
set -u
log="$(mktemp)"
pnpm --dir "$1" test --reporter=verbose --silent=false >"$log" 2>&1
code=$?
grep -E '^ +(Test Files|Tests) ' "$log"
echo "exit=$code warnings=$(grep -c -E 'stderr \||Warning|ENVIRONMENT_FALLBACK' "$log")"
```

**문구와 커밋**

- 문서·주석·검사·CLI 출력·UI 문구는 짧은 한국어다. 실패 메시지는 `<문제> — <방법>` 꼴이다.
- 경로·키·포트·이름 같은 바뀌는 값 바로 뒤에 조사를 붙이지 않는다. 값은 `:` 앞이나 괄호 안에 둔다. 새 테스트 제목의 `%s`·`%j`·`%d` 뒤도 같다(기존 제목은 Task 12가 바꾼다). 이 계획과 참고 구현에서 옮기는 메시지·문구는 글자 그대로 쓴다.
- 태스크마다 커밋 하나. 영어 Conventional Commits를 OS 임시 폴더의 메시지 파일로 `git commit --file`한다. 트레일러·AI 표시 없음, `--no-verify` 금지, 텍스트 파일만. push는 메인 worktree에서 하고 PR은 `gh pr create --assignee @me`로 만든다.

**생성 CLI 불변식**

- 생성할 템플릿·조합 자산·루트 `.gitattributes`·`.editorconfig`의 변경은 `pnpm new` 전에 커밋한다. CLI는 HEAD의 git 추적 파일만 복사하고(`template.json`, 무추적 환경 파일·설치물·캐시 제외) 인덱스의 실행 권한을 보존하며 비어 있지 않은 대상을 거절한다. CLI와 테스트의 git 호출은 `gitEnvironment()`를 쓴다.
- CLI 오류는 `CreateError(문제, 방법, 코드)`가 `pnpm new: <문제> — <방법>`으로 출력한다. 이 계획의 CLI 메시지는 `<문제> — <방법>` 부분이다. 사용법 오류는 exit 2다. FastAPI가 있는 프로젝트의 이름 `fastapi`, 조합의 이름 `api`·`web`·`admin`(`admin`은 Task 11부터)은 폴더 이름·`--name` 모두 거절한다. 단독 프로젝트는 `api`·`web`·`admin`을 허용한다.
- 조합은 루트 계약 하나의 추적 경로·바이트·실행 권한, 모든 프론트 importer·resolution·snapshot, pnpm 도구 문서, workspace 설정을 보존하며 다르면 생성 전에 거절한다.
