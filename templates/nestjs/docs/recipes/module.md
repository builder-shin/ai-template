# 모듈 추가

새 리소스의 TypeSpec·권한·에러·이벤트 계약을 먼저 합의하고 플랫폼 계약에 등록한다.
독립 프로젝트도 같은 계약 원칙을 따른다. 구현만 확장한 스펙은 기존 플랫폼 계약의
전체 비교에서 실패해야 한다. 비교 제외 목록이나 부분 비교로 숨기지 않는다.

1. `pnpm gen:module widgets`를 실행한다. 소문자 kebab 복수형을 쓴다(`blog-entries`도 가능하다).
2. 출력한 파일을 검토한다. 골든의 컨트롤러·서비스·저장소·정책·스키마·캐시·이벤트와 독립적인 단위 시험이 복사된다. 앱·include/파일 읽기 등록·파일 참조 보호·Prisma 모델 및 역관계·권한·에러·감사·실시간 선언과 엄격한 권한 예상 fixture도 갱신된다.
3. 필드·관계·권한 부여·로케일 문구와 공개 범위를 제품에 맞게 고친다. 복수형은 규칙적인 `s` 또는 `ies` 형태를 사용하고 단수형·테이블 이름을 검토한다. 골든의 표지 연결과 발행 상태가 필요 없는 제품은 관련 시험과 함께 명시적으로 변경한다.
4. `pnpm db:revision create_widgets`로 SQL 초안을 만들고 [마이그레이션 절차](migration.md)를 따른다. 생성기는 DB에 연결하지 않는다.
5. `pnpm gen`, `pnpm check --fast`를 실행하고 준비된 CI에서 전체 check·실제 API 흐름을 확인한다. 새 권한은 관리자 목록에 포함되지만 member 부여 여부는 따로 결정한다.

기존 디렉터리·모델·권한·등록과 충돌하거나 골든 등록 위치가 달라졌으면 쓰기 전에
실패한다. `src/generated/**`·`openapi.json`·기존 마이그레이션은 직접 고치지 않는다.
모듈 사이는 `index.ts`만 사용한다. 파일 관계를 더하면 같은 트랜잭션에서 살아 있는
참조를 확인하는 저장소 함수를 FilesModule에 함께 등록한다.
