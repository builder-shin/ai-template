# Native images and profile

The account screen updates name and locale through `/me`. A returned locale is adopted only after validating `ko` or `en` and the session generation. `/me?include=avatar` supplies the image relationship and its short-lived download URL. An expired or failed preview offers refresh without displaying its URL.

The image-only system picker requests the SDK 58 current/original representation with editing disabled and quality 1. It does not request access to the whole photo library in advance. Cancellation does not create metadata. Native permission failures offer **Open settings**; unknown device paths and errors are sanitized. Validate the actual MIME and size: the default images are JPEG/PNG/GIF/WebP, up to 10,485,760 bytes. Unsupported original formats are rejected by the existing MIME validation. The backend remains authoritative for its own configured limits and per-user quota. Review those public limits when changing the API's file policy.

`createNativeUploader(api, manager).uploadFile(file, {signal})` uses an SDK `File` as a Blob with `expo/fetch`. It creates pending metadata, sends the original presigned PUT URL and headers, then confirms `ready`. Storage requests omit API authorization, cookies and forwarding headers; redirects are errors. Raw control/backslash URLs, unexpected headers, expired descriptors and mismatched completion resources are refused. Release storage URLs must use HTTPS. No code rewrites a storage hostname or signature. For Android emulators, configure a storage address reachable from the device; a host-only `localhost` URL cannot be repaired after signing.

Caller cancellation and session changes stop the transfer and prevent late attachment. Known pending files are deleted on failure only within the same session generation. If a response is lost before its id arrives, the server's pending-file cleanup owns recovery (the backend purges old pending files). Upload errors never print filenames' local paths, signed URLs or credentials.

Avatar changes attach immediately. The posts editor holds a completed cover locally until Save; replacing or cancelling a known unsaved cover deletes only that new file. An original attached cover remains until the resource update removes it. A write with an unknown outcome may already have attached the file, so its file is retained rather than deleted automatically. Re-read the resource before retrying an ambiguous write. There is no automatic replay of write requests.

The test suite uses actual mock metadata/storage/download bytes and controlled HTTP failures: cancellation, permission errors, limits/quota, interrupted PUT, wrong completion, session expiry, account changes, profile and cover attach/remove, and unsaved-cover cleanup. Only native filesystem/picker transport ports are substituted in component tests. Device verification must additionally exercise Android/iOS system pickers, cancellation without broad photo access, supported/unsupported assets, image previews, reachable storage, background/foreground and revocation while transferring. Native E2E and real backend storage are separate CI gates; JS exports do not prove them.

SDK references: [FileSystem](https://docs.expo.dev/versions/v58.0.0/sdk/filesystem/), [ImagePicker](https://docs.expo.dev/versions/v58.0.0/sdk/imagepicker/).
