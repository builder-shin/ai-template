# 프로젝트 생성 CLI

저장소 루트에서 `pnpm new --help`로 단독·조합 생성 명령을 확인한다.

FastAPI가 있는 프로젝트는 이름 `fastapi`를 예약한다. 템플릿의 개발 compose 이름과 겹치므로 대상 폴더 이름과 `--name` 모두 거절하며, 다른 `--name`을 지정한다. 단독 nextjs는 허용한다. 다른 로컬 compose 프로젝트와도 이름이 겹치지 않도록 사용자가 고른다. 같은 이름은 볼륨을 공유한다.

조합은 앱의 workspace 패키지 이름인 `api`·`web`도 예약한다. 대상 폴더 이름과 `--name` 모두 오류 2로 거절하며, 다른 `--name`을 지정한다. 단독 프로젝트는 두 이름을 허용한다.

FastAPI 템플릿은 compose 이름을 고정하지 않는다. CLI는 생성한 `compose.yaml` 맨 앞에 설명 주석과 `name: <이름>`을 삽입하고 앱 이미지 값만 바꾼다. 템플릿에 이미 최상위 `name`이 있으면 지우도록 안내하고 실패한다.

CLI 위치가 git 저장소 루트와 맞아야 한다. Windows에서는 경로의 대소문자나 8.3 짧은 이름이 달라도 실제 같은 위치로 인정한다. 다른 폴더 구조에서 실행하면 배치 오류로 거절한다. 대상은 원본 저장소의 어느 worktree 안에도 둘 수 없다.

대상 경로의 드라이브나 공유를 찾을 수 없으면 폴더를 만들기 전에 거절하고 접근 가능한 위치를 지정하도록 안내한다.

실패는 `pnpm new: <문제> — <고치는 방법>` 한 줄로 알린다. 문제에는 시스템 오류 코드와 경로, 일반 오류 이름과 원인, git stderr의 첫 줄, 또는 잘못 지정한 옵션의 원인을 포함한다. 잘못된 이름을 포함한 사용법 오류는 종료 코드 2, 그 밖의 오류는 1이다. 기존 빈 폴더는 유지하고 생성한 항목만 넣는다. 실패하면 생성한 항목과 새 부모 폴더를 재시도하며 정리하고, 정리도 실패하면 원래 원인과 남은 경로를 함께 알린다.

생성 중 Ctrl+C로 중단하면 대상 옆의 임시 폴더 `aitpl-<이름>-XXXXXX`가 남을 수 있으므로 지운다. 새 대상은 완성한 임시 폴더를 한 번에 옮기지만, 기존 빈 대상에 항목별로 옮기는 도중 중단하면 대상도 일부 채워질 수 있으므로 생성된 항목을 비운다. CLI는 동기 실행이고 tsx 아래에서 돌며 Windows의 pnpm 자식은 숨겨서 실행하므로 중단 시 정리를 보장하지 않는다.

git 사용자 정보가 없으면 저장소를 초기화하고 파일을 스테이징한 뒤 `user.name`·`user.email` 설정과 출처를 담은 첫 커밋 명령을 안내한다.

첫 커밋은 복사한 템플릿 파일을 이름 목록으로 강제 추가하고 원본 인덱스의 실행 권한을 보존한다. 사용자의 전역 excludes가 `.env.example`, `.claude/`, `.mcp.json`을 무시해도 해당 파일을 빠뜨리지 않는다. 조합에서 새로 만든 파일도 프로젝트의 ignore 규칙에 따라 추가하며 설치물과 캐시는 포함하지 않는다.

조합 자산과 루트 `.gitattributes`·`.editorconfig`는 HEAD의 추적 내용만 복사한다. 이 입력에 미커밋 변경이 있으면 먼저 커밋하도록 안내한다. web 환경 예제의 API·실시간 키와 package.json의 엔진·도구 버전이 빠졌으면 설치 전에 고치도록 안내한다.
